해결한 문제

운영 중인 사이트에서 나온 사례입니다. 아래 4건 중 1건은 제가 낸 사고이고, 그 사실을 문서에 그대로 적었습니다.

문의가 안 들어오는데 화면은 멀쩡했다 — 정적 배포에서 서버 함수가 빠져 문의 API가 4시간 동안 405를 돌려주고 있었습니다. 400(요청이 잘못됨)과 405(경로는 있으나 메서드가 막힘)를 갈라 "언제부터 무엇 때문에"를 확정했습니다. 복구 후 배포 검증을 절차로 고정했습니다 — 도메인이 아니라 배포본 URL로 확인합니다(CDN 캐시가 지워진 파일에도 200을 줍니다).

최신본이 어디 있는지 아무도 몰랐다 — 운영 사이트의 소스가 git 어디에도 없었습니다. 로컬 후보 8곳을 라이브와 해시 대조한 결과 일치하는 것이 0곳. 라이브 산출물을 정본으로 확정해 고정하고 배포를 단방향으로 못박았습니다.

남의 서비스 장애가 우리 장애가 됐다 — 외부 무료 이미지 서비스를 직접 링크하고 있어 그쪽 장애 때 절반이 회색 박스가 됐습니다. 외부 핫링크 243건 → 0건, 234개 파일을 CC0로 선별해 자체 호스팅으로 옮겼습니다.

"AI가 만든 티"의 실제 원인 — 대개 내용이 아니라 기본기입니다. 한글 어절이 단어 중간에서 끊기는 문제를 Intl.Segmenter와 Range.getClientRects()로 세어 수치화했고, 운영 사이트 전체와 예시 25페이지에 적용해 0건으로 만들었습니다.
