## 해결하는 문제

운영 중인 사이트에서 나온 **7건**입니다. 숫자는 전부 제가 직접 측정한 값입니다.

**7건 중 2건은 제가 낸 사고입니다.** 어떻게 났고 어떻게 알아냈는지 같이 적었습니다.

- 광고는 돌리는데 문의가 안 들어온다 → 문의 API 가 **4시간 동안 405** 를 돌려주는 동안 화면은 정상으로 보였다
- 사진이 깨져 보인다 → 외부 이미지 핫링크 **243건 → 0건**, 전부 자가 호스팅으로
- 최신본이 어디 있는지 모르겠다 → 로컬 사본 **8곳 중 라이브와 일치하는 것 0곳**
- 뭔가 어색한데 뭐가 문제인지 모르겠다 → 한글 어절이 단어 중간에서 끊기던 것을 측정해 수치화

## 이 사이트를 제 방식으로 검사했습니다

제가 파는 것이 "화면은 멀쩡한데 죽어 있는 것을 찾는 일"입니다. 그러면 **제 사이트부터 그 기준을 통과해야 합니다.**

개편 전에 이 사이트를 직접 검사한 결과입니다. 전부 실측이고, 고친 뒤 값을 함께 적었습니다.

| 검사 | 개편 전 | 개편 후 |
|---|---|---|
| 본문 단어 수 (JS 실행 전) | **0** — `<div id="root">` 뿐 | 실제 본문 |
| 하위 경로 응답 | `/problems` 등 **전부 404** | 200 |
| 404 페이지가 참조하는 에셋 | **둘 다 404** → 404 상태의 백지 | 살아 있음 |
| `canonical` | **남의 도메인**을 가리켜 스스로 색인 포기 | 자기 주소 |
| `robots.txt` · `sitemap.xml` | **둘 다 404** | 실제 파일 |
| 이력서 파일 | **404** (없었음) | 있음 |
| 커밋 작성자 이름 | **두 가지가 섞여 있었음** | 하나로 |

원인은 하나였습니다. 이 사이트는 다른 사이트의 **빌드 산출물 미러**였고, GitHub Pages 에는 SPA 폴백이 없어서 하위 경로가 전부 죽어 있었습니다. 미러를 끊고 정적 페이지로 다시 발행했습니다.

> 고치기 전 상태를 지우지 않고 그대로 둡니다. 이 표가 없으면 위의 주장은 확인할 방법이 없습니다.

## 판별 절차

형용사 대신 **남이 따라 할 수 있는 절차**로 적었습니다.

- **400 과 405 로 경계 만들기** — 경로가 없는 것과 메서드가 막힌 것을 가르면 "언제부터, 무엇 때문에"가 확정됩니다
- **해시 대조로 정본 판정하기** — 사본이 여러 개일 때 어느 것도 정본이 아닐 수 있습니다
- **어절 쪼개짐 측정** — 한국어 레이아웃 붕괴를 눈이 아니라 숫자로 셉니다
